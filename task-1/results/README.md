# Задание 1. Выбор и реализация решения для пакетной обработки данных

## Нефункциональные требования

- Расчетный объем обработки - около миллиона записей за запуск.
- Пайплайн должен допускать подключение новых источников и изменение порядка обработки.
- При временных сбоях нужны повторные попытки, а для контроля работы - статусы, логи и уведомления.
- Локальное решение должно иметь возможность дальнейшего развертывания в облаке.

## Решение

- Выбран Apache Airflow: он управляет зависимостями задач, поддерживает ветвление по условиям и показывает ход выполнения в веб-интерфейсе.
- Для BigQuery, Redshift, Kafka, Spark и внешних API есть готовые модули подключения.
- Пайплайн можно запускать по расписанию, вручную или по событию.
- Airflow поддерживает повторные попытки и отправку email об успехе или ошибке. При сбое можно настроить запасную ветку обработки.
- В облаке Airflow можно развернуть в Kubernetes, чтобы задачи выполнялись отдельно и ресурсы можно было увеличивать при росте нагрузки.

## Альтернативы

- Cron со скриптами проще для одной выгрузки, но зависимости шагов, повторы и контроль всего пайплайна пришлось бы организовывать отдельно.
- Spring Batch удобен для пакетной обработки в Java, но для управления разными внешними системами в этой задаче удобнее готовые интеграции Airflow.

## Запуск

Запуск:

```sh
docker compose up -d
```

Остановка:

```sh
docker compose down -v
```
